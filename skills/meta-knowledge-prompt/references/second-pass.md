# 已经改过一次，下一轮怎么写

用户说“还是不对”时，找回原要求和新结果。当前对话已经有的材料不必再索要。先问自己：上次哪一条意图已经满足，第一次偏差出现在哪里？优先修能解释问题的最小一处。

| 实际变化 | 判断依据 | 下一条指令该改什么 |
|---|---|---|
| 指令里有要求，成品漏了 | 例如明确要求常驻四项，成品折叠两项 | 点名漏掉的两项和它们的使用场景，保留已生效的排序；给一个不展开即可检查的任务 |
| 所有指令都执行了，问题还在 | 例如说明已折叠，但试用者仍找不到上传按钮 | 回到现场证据，改查入口的视觉层级或词义；换假设，避免继续折叠 |
| 改到了用户很在意的内容 | 例如开场更快，却把真实维修原因提前说破 | 明确哪块要恢复，保留有效的节奏改动，用一句反例说明什么算剧透 |
| 下游工具缺少输入或能力 | 例如写了剪辑指令，聊天工具既拿不到视频也无法导出成片 | 先确认可用输入，让它交付能用的时间线方案或把指令转给可处理视频的工具；时间码只能来自实际素材 |
| 只有“还是怪怪的” | 如果选错原因，下一轮会往不同方向改 | 问一个能定位差异的问题，例如“观众现在是没看到报名时间，还是看见时间却不知道去哪报名？” |

**可复制的补丁示例**：上一版把 MOV 帮助推迟到出错时出现，这点保留。现在用户选错文件会看到“格式错误”，却找不到怎么处理。请只改选错格式后的文案：说明工作台接受 MP4，给“重新选择文件”按钮和现有转换教程入口。交付这个状态的完整文案。检查用户从出错到重选能否一步到达。

一次修改能让人看出哪个变化起作用时就停。如果作品和上一条指令都缺失，可以先请用户给出最让他介意的一处原文或截屏。不要声称已验证未见过的新版本。
